# 퇴근요정 (GTFO: Gracefully Terminate Formal Obligations)

**현재 버전: ver 3.0** (2026-11-09) — 3.0: **인쇄 기능**(스크롤/부분 캡처 이미지를 쪽 나눠 인쇄, 미리보기·프린터 선택). 이전: 2.9 (2026-11-06) — AI 칸 읽기 보정 정확도 — 칸 그림을 '열 전체 × 행 전체'로 잘라 `이관→이권` 오류 해결(OCR 단어 상자가 가로·세로로 어긋나 글자가 잘리던 것). 이전: 2.8: DCI 썸네일 열 잡글자 자동 비우기, 칸 그림 읽기 AI 보정 속도 4배(동시 2개·첫 읽기가 맞으면 종료), OCR 중복 단어 제거. 이전: 2.7: DCI `AI로 보정`을 **칸 그림 읽기**로 교체(칸을 한 칸씩 잘라 여러 배율로 읽고 다수결, 같은 열 후보 제공), OCR에 '어둡게'(감마) 변형 추가. 사용자 표에서 정확한 칸 54/72 → 66/72(`천신`·`승인완료`·`노출`·상품코드·`운전` 정정). 이전: 2.6: DCI `AI 띄어쓰기 보정`(칸이 좁아 줄바꿈된 단어 `자 기소개서`·`경력기 술서`를 로컬 AI가 이어 붙임, 글자는 그대로). 이전: 2.5: DCI 테이블 — 셀 안에서 여러 줄로 줄바꿈되는 표(썸네일·긴 제목)가 일부 행만 나오던 문제 수정(행 구분선 기준 레코드 모드), 정밀 OCR(여러 설정) 옵션, 칸 안 줄 순서 뒤섞임 수정, 넓은 표 AI 보정 경고. 이전: 2.4: DCI 테이블 캡처에 `AI로 보정` 추가(로컬 AI가 이미지를 보고 틀린 칸 수정). 이전: 2.3: 운영 > AI캡쳐하기(텍스트 캡쳐하기 + 로컬 AI 보정, 이미지 캡쳐하기 → 프롬프트 만들기, Gemma 4 E2B). 이전: 2.2: 메뉴 개편(운영 1depth · Data&Url캡쳐 · 텍스트 캡쳐하기), 텍스트 캡쳐 품질 개선(여러 설정 OCR·카드/단 자동 분리), 작업표시줄 퇴근요정 아이콘/이름. 이전: 2.1: 단축 URL 인식 개선(0/O/o, utm 키 복원, 잡글자·모양 불일치 후보 대입, 누락 글자 복구), 접속 확인 속도 개선(동시 요청, ESC 중단), DCI 숫자 열 보정. 이전: 2.0 (2026-11-05) — 창 제목줄과 상단 헤더에 표시됩니다. 기능을 고칠 때는 `app.py`의 `VERSION`/`BUILD_DATE`를 올리세요.

이니시스(KG) 정산 화면을 **캡처 → 로컬 OCR → 분개 엑셀 양식 → 영림원 붙여넣기**까지 이어주는 Windows PC 앱입니다.
영림원처럼 API/MCP를 쓸 수 없는 프로그램에 화면 캡처와 클립보드 붙여넣기만으로 입력합니다.

- **100% 로컬 처리**: 화면 이미지는 외부로 전송되지 않습니다 (Windows 내장 한국어 OCR 사용).
- 환경: Windows 10/11, Python 3.12, tkinter

## 설치 및 실행

```bash
python -m pip install -r requirements.txt
```

설치 후 `GTFO.lnk`(캐릭터 아이콘 바로가기, 콘솔 창 없이 실행)나 `run.bat`을 더블클릭하거나 아래 명령으로 실행합니다. (최초 1회만 설치)
`GTFO.lnk`는 이 PC의 Python 경로를 가리키므로, 폴더를 다른 PC로 옮겼다면 `run.bat`을 쓰거나 바로가기를 다시 만드세요.

```bash
python app.py
```

> Windows 설정에서 한국어 언어팩(OCR 포함)이 설치되어 있어야 합니다.

### 환경 설정 (`local_config.py`)

회사/환경마다 다른 값(단축 URL 서버 호스트, 원본 URL 호스트, PG 상점 ID, 분개 적요 말머리, 작업표시줄 앱 ID)은 코드에 넣지 않고 설정 파일로 분리했습니다.
`local_config.example.py`를 `local_config.py`로 복사해 값을 고치세요. (`local_config.py`는 `.gitignore`로 git에 올라가지 않습니다. 없으면 `config.py`의 예시 값(`short.example` 등)으로 동작하며, 이 경우 단축 URL 접속 확인은 의미가 없습니다.)

### AI 기능(선택)

`운영 > AI캡쳐하기`와 DCI 테이블의 `AI로 보정`은 이 PC의 로컬 AI를 씁니다: `winget install Ollama.Ollama` 후 `ollama pull gemma4:e2b`. 설치하지 않아도 나머지 기능은 모두 동작합니다.

## 사용 방법

1. 이니시스에서 해당 화면을 조회합니다.
2. **화면 영역 캡처**를 누르고, 표의 **헤더 + 데이터 행만 좁게** 드래그합니다. (합계 행 제외, 화면 전체를 잡으면 인식률이 떨어집니다)
3. 읽힌 값과 검증 표시(✔ 일치 / ⚠ 차이)를 확인하고 필요하면 수정합니다.
4. **클립보드 복사** 후 영림원 그리드에서 `Ctrl+V` 하거나, **엑셀로 저장**합니다.

### 선급금/미지급금 처리
- 구분: `매월 8일 미지급금` / `매월 22일 선급금`
- 캡처 대상: **통합정산내역조회**
- 상점ID × 정산기간마다 3줄 생성: 예치금-pg(차) / 미수금-PG(카드)(대) / 미지급금-PG 또는 선급금-PG(차, 수수료+부가세)

### PG(이니시스) 수수료 정산
- 대상 상점: 설정(`local_config.py`의 `STORE_IDS`)에 적은 상점들
- 캡처 대상: **세금계산서 발행내역조회**(공급가액·세액), **통합정산내역조회**(정산일 1~15일 / 16일~말일)
- 상점당 4줄 생성: 지급수수료-PG수수료(판관) / 부가세대급금 / 선급금-PG(대) / 미지급금-PG(대)
- 선택 입력: 계좌성명조회 등 기타 수수료 (미지급금-거래처)

### DCI 테이블 캡처 (운영 > Data&Url캡쳐) — `AI로 보정` (ver 2.4)
표 옵션 줄의 **AI로 보정 (틀린 칸 고치기)** 는 이 PC의 로컬 AI(Gemma 4 E2B, 사용 조건은 아래 'AI캡쳐하기' 참고)가 이미지를 보고 OCR 표의 틀린 칸을 고칩니다.
- 표를 **12행 구간**으로 나눠, 구간마다 해당 행의 이미지 조각 + OCR 초안(머리글 포함)을 보냅니다. 돌아온 표의 **행·열 수가 같을 때만** 반영하고, 빈 칸으로 지우는 변경은 무시합니다(건너뛴 구간은 상태줄에 표시).
- 바뀐 칸 표시: **글자만 바뀐 칸 = 연노랑**, **숫자·날짜가 바뀐 칸 = 주황(확인 필요)**. 주황 칸은 `표 데이터 복사` 때 엑셀에서도 **노란 배경**으로 붙습니다(고치지 않은 값처럼 조용히 들어가지 않게). 칸을 직접 수정하면 표시가 사라집니다.
- `AI 보정 되돌리기`로 OCR 원문 복구, 실행 중에는 같은 버튼이 `AI 중단`. `확인 필요(노란) 행 주변만`을 켜면 의심 행 주변만 AI에게 맡겨 빠릅니다.
- 시험(합성 결제표 26행×6열, 13px): 정확한 칸 **100/162 → 156/162**(AI가 고친 56칸, 맞는 값을 망친 칸 0). 남은 6칸은 OCR이 틀린 값(`스팟 공고`→`스팟 광고` 등)을 AI도 못 고친 것. 속도는 26행에 약 80초(CPU).
- **`AI로 보정 (칸 그림 읽기)`** (ver 2.7, 표 전체를 한 번에 읽히던 방식을 대체): 글자가 든 칸을 **한 칸씩 잘라**(작은 그림일수록 로컬 AI가 정확) 1배·3배로 읽고, 같으면 확정·다르면 5배로 한 번 더 읽어 다수결합니다. 같은 값의 칸(모든 행의 판매자·승인상태 등)은 **한 번만 읽어 전체에 적용**합니다. 같은 열의 비슷한 OCR 값들(`노훋/노푿/노출`)을 **후보로 보여 주면** 진짜 단어를 골라 정확해집니다(후보가 하나뿐이면 틀린 값을 따라 하므로 후보 없이 읽음). AI 값이 OCR 값과 너무 다르면(지어낸 값) 버립니다. 표시: 연노랑=글자 수정, **주황=숫자가 바뀜(엑셀에서 노란색)**, **분홍=읽기가 갈려 판단 못 함(바꾸지 않고 확인 필요, 엑셀에서 노란색)**. 썸네일 잡글자 칸은 건너뜁니다. 숫자·날짜만 있는 칸은 OCR을 믿고 AI에 맡기지 않습니다. 시험(사용자 표 7행×17열): **정확한 칸 54/72 → 66/72**, 상품코드 6/6, `천신`·`승인완료`·`노출`·`운전`·`경력기술서` 정정. 느림(칸 종류 48개에 약 3.5분) — `확인 필요(노란) 칸만`을 켜면 의심 칸만 읽어 빠릅니다. 아직 못 고치는 것: `서류 작성 코칭`→`고청`(획이 얇은 글자는 AI도 틀림).
- **썸네일(그림) 열 잡글자 자동 비우기** (ver 2.8): 썸네일 그림 속 작은 글자를 OCR이 읽어 `11뙤 LI it爻 주,3으렛!` 같은 의미 없는 글자가 칸에 들어가던 문제. 비어 있지 않은 칸이 3개 이상이고 그 75% 이상이 '지어낸 글자'(한자, 한글+숫자/소문자 영문이 한 단어에 섞임, 이상한 기호; `26년`·`10월`·`DATA동기화` 같은 정상 형태는 제외)인 열을 그림 열로 보고 칸을 비웁니다(머리글은 유지, 열 위치는 그대로). 상태줄에 `그림(썸네일) 열 N개의 잡글자를 비움`이 표시됩니다. 오판으로 지워졌다면 `OCR 다시`에서 `정밀 OCR`을 끄고 확인하세요.
- **AI 보정 속도 개선** (ver 2.8, 사용자 표 4행 기준 83초→23~26초, 7행 17열 149초→34~39초): ① **동시에 2개씩 읽기**(Ollama가 CPU에서 2개까지 병렬로 1.45배, 3개 이상은 효과 없음) ② **첫 읽기가 OCR 값과 같으면 바로 종료**(대부분의 칸), 다르면 2·3번째 읽기로 다수결 ③ 칸 그림 크기 상한(긴 변 200/420/760px, 최대 10배) ④ 썸네일 잡글자 칸은 건너뜀. 읽기 1회는 0.5~1.5초(그림이 크고 답이 길수록 느림). 어두운 바탕 칸(초록 버튼 흰 글자)은 반전해서 읽습니다.
- **OCR 중복 단어 제거** (ver 2.8): 설정마다 단어 상자 위치가 달라(세로 16px까지) `5,000 5,000 5,000`처럼 같은 단어가 여러 번 들어가던 것을 합칩니다.
- **칸 그림 자르기 개선** (ver 2.9): AI가 맞는 값을 `이관`→`이권`으로 바꾸던 원인은 AI가 아니라 **그림이 글자를 잘라서**였습니다. OCR 단어 상자는 설정마다 가로로 수십 px, 세로로 16px까지 어긋나(타일 경계 근처) 단어 상자대로 자르면 '관'의 일부가 잘렸습니다. 이제 칸 그림을 **가로는 그 열 전체의 글자 범위, 세로는 그 행의 범위(행 구분선 사이)**로 넉넉히 자릅니다. 배율은 크롭 크기가 아니라 **글자 높이** 기준(30/46/64px)으로 키우고 긴 변 1100px 상한. 시험: `이관` 4행 모두 정상, 두 표에서 `천신`·`승인완료`·`노출`·`운전`·상품코드 유지.
- 알려진 한계: AI가 맞는 OCR 값을 틀리게 바꾸는 일이 아직 있을 수 있습니다(`등록일`→`등복일`). 바뀐 칸은 연노랑으로 표시되니 검토하세요(되돌리기 가능). 시도했다가 버린 '칸 그림을 Windows OCR에 한 번 더 넣어 투표' 방식은 Windows가 같은 글자를 같게 틀려(`전신`) 가려내지 못했습니다.
- AI 보정 시간은 PC 상태에 따라 달라집니다(같은 표 4행: 23초~100초, 7행: 34초~160초). 시간이 길면 `확인 필요(노란) 칸만`을 켜거나 다른 프로그램을 닫으세요.
- **AI 띄어쓰기 보정** (ver 2.6): 칸이 좁아 글자가 줄바꿈되면 단어 중간에서 끊겨 줄을 이을 때 공백이 끼는 문제(`자 기소개서`, `경력기 술서`, `이력 서`)를 고칩니다. 공백이 있는 6자 이상 한글 칸을 **텍스트로만** 로컬 AI에 보내(이미지 없음, 20칸씩, 6칸에 약 6~16초) 띄어쓰기만 고치게 하고, 돌아온 문장의 **공백 위치만 OCR 원문 글자에 입힙니다** — 글자 수가 다르면 버리고, AI가 오타를 고쳐 써도 글자는 원문 그대로라 글자가 바뀌지 않습니다. 바뀐 칸은 연노랑, `AI 보정 되돌리기`로 복구. 시험(사용자 표 6칸 중 4칸 교정, 1칸 `경력 기술서`는 그대로 둠).
- **여러 줄 셀 합치기(행 구분선 기준)** (ver 2.5, 기본 켬): 행마다 칸 안이 2~3줄로 줄바꿈되고 썸네일이 있는 표(상품 목록 등)를 줄 단위로 읽으면 한 행이 여러 블록으로 쪼개져 일부 행만 나왔습니다. 행 사이 구분선(왼쪽 가장자리 배경색 변화)이 규칙적으로 보이면 **구분선 사이 = 한 행**으로 만듭니다(영역을 표 왼쪽 끝에 맞추면 잘 잡힘). 구분선이 없으면 기존 방식(블록 자동 선택).
- **정밀 OCR**(기본 켬, 약 7~10초): 여러 배율·선명화로 읽어 줄마다 가장 좋은 결과를 씁니다(`등독일→등록일`, 상품코드가 맞게 나옴). 끄면 1~2초.
- **넓은 표의 AI 보정 한계**: 16열×7행·1593px 표 시험에서 작은 로컬 AI가 칸을 어긋나게 읽어 구간이 건너뛰어졌고(51초), 칸 목록 방식도 90초에 틀린 값이 섞였습니다. 열이 10개 넘거나 폭 1400px 넘는 표는 실행 전에 경고합니다. 이런 표는 정밀 OCR 결과를 직접 확인하세요.
- 쓸 수 없는 경우: `모든 블록` 상태, 표 행 수를 직접 바꾼 뒤(→ `OCR 다시`로 표를 새로 만든 뒤 사용). 단축URL 캡처에는 AI 보정이 없습니다(ID는 서버 접속 확인이 더 정확).
결제 목록처럼 행/열이 있는 화면을 캡처해서 **화면의 항목과 값이 엑셀의 각 행/열로** 붙여넣어지게 합니다. (단축URL 캡처와 스크롤 캡처·이미지 복사·저장 기능은 같습니다)

1. 표가 포함된 영역을 지정합니다. 검색 폼·제목이 섞여 있어도 **세로 여백으로 블록을 나누고 가장 큰 표를 자동 선택**합니다. 다른 블록은 `대상 표`에서 고르거나 `모든 블록`을 선택합니다.
2. 넓은 화면은 **가로 타일로 나눠 지정한 배율(기본 3.0)대로 OCR**합니다. (OCR 엔진은 큰 이미지의 배율을 자동으로 깎아서, 폭 1659px에서는 작은 글자가 안 읽혔습니다)
3. 열은 블록마다 따로 계산하고, 빈 셀(예: 결제일 비어 있음)도 제자리에 둡니다.
4. `보정(날짜·고유번호·반복값)`(기본 켜짐): 날짜 `2026-11-05 145625`, `2026•11-05 14 5820` → `2026-11-05 14:56:25`, `mem—idx` → `mem_idx`. 그리고 **같은 열의 다른 값과 비교**해서 바로잡습니다.
   - **고유번호 열**(예: 9자리 재무연동번호)에서 `31541 4295`처럼 갈라진 값은 열의 일반적인 길이로 합칩니다.
   - 같은 값이 반복되는 열에서 공백만 다른 값(`주문서 비스` → `주문서비스`)은 대표 값으로 맞춥니다.
   - **숫자 열**(순수 숫자가 절반 이상, 고칠 수 있는 값까지 합치면 80% 이상)에 끼어든 숫자 닮은 글자는 숫자로 되돌립니다: `O`/`o`/`Q`/`D`→0, `l`/`I`/`|`→1, `S`→5, `B`→8 (예: `9,9O0`→`9,900`, `2I529`→`21529`). 글자 열(`Dodo`, `Oslo`)은 건드리지 않습니다.
   - **거의 항상 같은 두 날짜 열**(재무연동날짜=신청일)에서 한쪽만 깨졌으면 다른 쪽 값으로 채웁니다. (서로 다른 값이 정상인 열은 건드리지 않습니다)
   - 그래도 의심스러운 셀(이상한 글자, 형식이 깨진 날짜, 길이가 다른 고유번호)은 복사하면 **엑셀에서 연노랑 배경**으로 표시됩니다. 상태줄에 개수가 나옵니다. 노란 셀만 화면과 대조하세요.
   - 갈라진 번호의 원인이었던 **가로 타일 경계**(숫자 사이 1~2px 틈에서 잘리던 문제)도 고쳤습니다. 이제 가장 넓은 빈 구간의 중앙에서 자릅니다.
5. **표 데이터 복사** → 엑셀에서 `Ctrl+V` 하면 셀로 나뉘어 붙습니다. 결과 텍스트 상자에서 직접 고칠 수도 있습니다.
   - 탭 구분 텍스트만 붙이면 엑셀이 `2026-11-05 14:56:25`를 날짜로 바꾸고 **초를 숨깁니다**(`2026-11-05 14:56`), 앞이 0인 값(`00123`)은 `123`으로, 15자리 숫자는 `1.23E+14`로 망가집니다. 그래서 텍스트와 **HTML 서식을 함께** 복사합니다: 날짜/시간은 `yyyy-mm-dd hh:mm:ss` 날짜 값(초까지 표시, 정렬 가능), 앞이 0이거나 12자리 이상인 숫자는 텍스트, `9,900`은 숫자. (엑셀 COM으로 붙여 넣어 확인)
   - `엑셀로 저장`도 같은 규칙입니다(날짜 값 + 서식, 긴 숫자는 텍스트).
   - **앱을 수정본으로 다시 실행해야 반영됩니다.** 파이썬은 시작할 때 코드를 읽으므로, 업데이트 후에는 GTFO를 닫았다가 `GTFO.lnk`로 다시 여세요.
- 화면 밖으로 잘린 열(가로 스크롤이 필요한 열)은 읽을 수 없습니다. 보이는 범위만 읽힙니다.
- 마지막 열이 잘려 있으면 값이 일부만 읽힙니다. 열이 잘리지 않게 브라우저 폭/배율을 조정하세요.
- 글자가 작으면 OCR 배율을 올려 `OCR 다시`를 누르세요. 열이 합쳐지거나 갈라지면 `열 간격 민감도`를 조절하세요.

#### 캡처 중 안내 말풍선
스크롤 캡처가 진행되는 동안 마우스 커서 옆에 **"퇴근요정이 화면캡쳐중입니다. 잠시만 기다려주세요"** 말풍선(캐릭터 아이콘, 스크롤 횟수, ESC = 중단)이 떠서 마우스를 건드리지 않도록 알려 줍니다. 캡처가 끝나면 사라집니다. (`capture_tip.py`)
- **캡처 이미지에는 찍히지 않습니다.** Windows의 "화면 캡처에서 제외" 기능을 쓰며(Windows 10 2004 이상), 지원되지 않는 환경에서는 캡처하는 순간에만 잠시 숨깁니다.
- 클릭/휠이 그대로 통과하고 창을 활성화하지 않으므로 VDI로 가는 스크롤 입력과 포커스를 방해하지 않습니다.
- 문구는 `capture_tip.py` 의 `LINES` 에서 바꿀 수 있습니다.

#### 끝까지 캡처되지 않고 마지막 내용이 빠질 때
- **원인:** 페이지를 끝까지 내리면 마지막 내용은 **창 안의 페이지 화면(뷰포트) 맨 아래**에 놓입니다. 선택한 영역이 그 화면보다 짧으면(예: 높이 232px) 그 부분은 스크롤하는 동안 한 번도 영역 안에 들어오지 않아서 마지막 몇 행이 통째로 빠졌습니다. (`scroll_capture.log`에서 정상 종료 `끝까지 스크롤`인데 내용이 모자란 경우)
- **고침:** 끝에서 영역을 창 아래쪽까지 늘려 한 번 더 찍고, 위로 한 칸 올려 비교해서 **스크롤되는 부분만** 이어붙입니다(작업표시줄 같은 정지 영역은 제외). 화면의 `끝에서 영역 아래쪽 내용도 포함`(기본 켜짐)으로 끌 수 있고, 로그에 `끝 위치에서 영역 아래쪽 Npx 추가`가 남습니다.
- **고정 영역 오인 수정:** 내용이 듬성듬성한 페이지에서는 빈 흰 줄도 "스크롤 전후에 같은 줄"이라 고정 영역으로 오인해서, 마지막 프레임의 아래쪽 몇 px가 빠지고 정합이 불안정했습니다. 이제 글자/선이 있는 줄만 고정 영역으로 인정합니다.
- **시작 위치:** 캡처는 **영역 위쪽이 가리키는 곳**부터 시작합니다. 그보다 위의 내용(영역 위쪽~화면 위쪽)이 필요하면 영역을 위쪽까지 크게 잡으세요.
- 고정 푸터가 마지막 내용을 덮고 있으면(스크롤해도 푸터 아래에 가려짐) 그 부분은 눈으로도 보이지 않으므로 캡처되지 않습니다.

#### 같은 모양의 줄이 반복되는 페이지의 이어붙이기
목록·문단처럼 줄마다 숫자만 다르고 모양이 거의 같은 화면에서는, 서로 다른 이동량(예: 200px, 34px, 68px)이 비슷한 점수로 비길 수 있습니다. 예전에는 비기면 "비교한 줄이 가장 많은 = 가장 작은 이동량"을 골라 엉뚱한 위치에 이어붙였습니다(합성 38줄 이미지에서 1300px 중 552px만 이어붙음). 이제 비기면 **원본 해상도 픽셀로 겹친 부분의 오차를 비교**해서 가장 맞는 이동량을 고릅니다(1300/1300, 38줄 모두 읽힘).

#### 스크롤이 되지 않을 때
영역 지정 후 마우스가 영역 중앙으로 옮겨지고, **그 위치의 창**으로 휠이 전달됩니다(영역을 드래그한 곳이 대상이며, 이전에 마우스가 있던 곳은 상관없습니다). 캡처 중에는 매 스크롤마다 마우스를 영역 중앙으로 되돌립니다.
- 대상 창(VDI 뷰어)을 클릭 없이 앞으로 가져오고, 마우스 이동 입력을 보내 위치를 알립니다.
- 첫 스크롤에 화면이 안 변하면 **큰 휠 → PageDown → ↓ → Space** 순서로 자동 전환하며, 어떤 방식이 먹혔는지 상태줄에 표시합니다.
- 끝이라고 판단하기 전에 두 번 더 기다리고 스크롤합니다(VDI 지연으로 입력이 유실된 경우 대비).
- 순서에 **창 메시지(WM_MOUSEWHEEL) 직접 전송**도 포함됩니다(시스템 입력이 전달되지 않는 환경 대비).
- 매 캡처마다 **진단 로그**가 `scroll_capture.log`(GTFO 폴더)에 저장됩니다: 대상 창 이름/클래스, 활성화 성공 여부, 각 방식별 화면 변화량. 스크롤이 안 되면 이 파일 내용을 알려주세요.
- 그래도 안 되면 "스크롤이 반응하지 않았습니다" 경고(진단 로그 포함)가 뜨고 지금 화면만 캡처됩니다.
  (상태줄에 `… · 끝까지 스크롤`이 뜨면서 한 장만 나왔다면 **수정 전 버전**이 실행 중인 것입니다 — 앱을 다시 실행하세요.) 이때는 `영역 중앙 클릭(포커스)`을 켜거나 VDI 창을 한 번 클릭한 뒤 다시 시도하고, 스크롤 방식을 `PageDown 키`로 바꿔 보세요.

### 인쇄 (모든 캡처 화면 공통, ver 3.0)
단축URL 캡처·DCI 테이블 캡처·텍스트 캡쳐하기·이미지 캡쳐하기 화면 아래쪽의 **`인쇄…`** 버튼이 지금 가져온 캡처 이미지(스크롤 캡처·영역 캡처·파일·클립보드 모두)를 인쇄합니다. 옵션 창에서 고릅니다.
- **맞춤 방식**: `폭에 맞춰 여러 쪽`(기본 — 용지 폭에 맞추고 긴 이미지는 여러 쪽으로 나눔; **쪽 경계는 글자가 없는 가로줄에서 잘라 글자가 갈라지지 않음**) / `한 쪽에 맞춤`(전체를 한 장에, 비율 유지)
- **용지 방향**: `자동`(가로로 넓은 이미지는 가로 용지) / `세로` / `가로`. 옵션 창에 `A4 기준 N쪽`이 미리 표시됩니다.
- **쪽 아래 바닥글**: `퇴근요정 · 날짜 시각 · 쪽/전체` (끌 수 있음)
- **미리보기…**: Windows 인쇄 미리보기(쪽 이동·확대·인쇄 버튼) / **프린터 선택해 바로 인쇄…**: Windows 인쇄 창(프린터·매수·쪽 범위 선택) 후 인쇄. 프린터는 이 PC에 설치된 것을 씁니다.
- 작은 이미지는 부드럽게 키워(최대 3배, 폭 1600px 기준) 선명하게 인쇄합니다. 추가 설치는 없습니다(Windows 기본 인쇄 기능을 PowerShell로 호출, `printing.py`).
- 실제 프린터로의 출력과 'Microsoft Print to PDF'는 이 PC에서 직접 시험하지 못했습니다(미리보기까지 확인) — 처음 쓸 때 한 번 확인해 주세요.

### AI캡쳐하기 (운영) — 로컬 AI(Gemma 4 E2B) 사용
이 PC에서만 도는 **Ollama + Gemma 4 E2B**(Apache 2.0, 약 4.6GB)를 씁니다. 이미지·결과는 밖으로 나가지 않습니다. 이 PC(i7-1360P, GPU 없음, RAM 31.6GB)에서는 CPU로 돌리며 **10~60초** 걸립니다.
- 설치: `winget install Ollama.Ollama` → `ollama pull gemma4:e2b` (이미 설치됨). 퇴근요정이 꺼져 있는 Ollama 서버를 알아서 켭니다(`aillm.py`). 없으면 버튼을 눌렀을 때 설치 안내가 나옵니다.
- 시험 결과(카드 4장 합성 이미지): Windows OCR만 → 로고(ENF, KTR, BORYUNG)·작은 글자·날짜 누락/오인식 / **Windows OCR 초안 + AI 보정 → `한국알콜산업 계열사`, `한국화학융합시험연구원`, `D-3`까지 복구 (14초)**. 반면 AI가 이미지만 보고 직접 읽으면 `하반기→한방기`처럼 지어내는 글자가 있어, **OCR 초안을 함께 주는 방식**을 씁니다. 일반 문단에서도 `바꿔 줍니다`→`바꿉니다`처럼 말투를 바꾸는 일이 있어 **바뀐 줄을 노란색으로 보여 주고 되돌리기**를 둡니다.
- 쓰지 않는 곳: 단축 URL ID, 정산 금액(AI가 그럴듯한 값을 만들 수 있음 — 서버 접속 확인·합계 검증 유지).

#### 텍스트 캡쳐하기 (AI캡쳐하기 > 텍스트 캡쳐하기)
`AI로 보정` 버튼 — 현재 텍스트와 이미지를 AI에게 보여 주고 틀린 글자·빠진 글자를 고칩니다(바뀐 줄 노란색, `AI 보정 되돌리기`로 원문 복구, 실행 중 같은 버튼이 `AI 중단`). 아래 설명의 기본 OCR 기능은 그대로입니다.

#### 이미지 캡쳐하기 (AI캡쳐하기 > 이미지 캡쳐하기)
가져오기(영역·스크롤 캡처, 파일, 클립보드)는 텍스트 캡쳐하기와 같고, `프롬프트 만들기`가 이미지를 보고 프롬프트를 씁니다. 만들 것: `이미지 생성 AI용 프롬프트` / `화면(UI) 구현용 프롬프트` / `이미지 설명(대체 텍스트)` / `직접 지시`(예: "이 표를 마크다운으로 바꿔줘"). 답 언어는 한국어/English. `이미지 속 글자(OCR)도 참고로 전달`(기본 켬)은 AI가 작은 글자를 지어내는 것을 줄입니다(+약 4초). 결과는 수정·복사·.txt 저장 가능.

### 텍스트 캡쳐하기 (운영 > AI캡쳐하기)
이미지 속 글자, 또는 **텍스트 선택·복사가 안 되는 웹페이지/VDI 화면**의 글자를 화면 픽셀에서 읽어 텍스트로 뽑습니다. 모든 처리는 이 PC에서만 합니다(Windows 내장 OCR).

**① 가져오기** — 네 가지 중 하나를 고릅니다.
- **화면 영역 캡처 (스크롤 없음)**: 드래그한 영역만 한 장 캡처
- **영역 지정 + 자동 스크롤 캡처**: 긴 페이지를 위에서 아래로 스크롤하며 한 장으로 이어붙임 (단축URL/DCI와 같은 기능: 창 활성화·자동 전환·끝에서 아래쪽 보충·안내 말풍선)
- **이미지 파일 열기…**: png·jpg·webp·bmp·gif·tif (휴대폰 사진의 회전 정보 반영)
- **클립보드 이미지 붙여넣기**: `Win+Shift+S` 캡처나 복사한 이미지, 탐색기에서 복사한 이미지 파일

**② 추출된 텍스트** — 읽은 뒤 설정만 바꾸면 **재인식 없이** 바로 다시 정리됩니다.
| 옵션 | 설명 |
|------|------|
| 줄바꿈 | `줄 그대로` / `문단으로 합치기`(줄 간격이 1.35배 넘게 벌어지거나 짧게 끝나는 줄 뒤에서 문단을 나누고, 같은 문단의 줄은 공백으로 이음. 영어 하이픈 줄바꿈도 합침) / `한 줄로` |
| 다단(2단 이상) 읽기 | 세로로 넓게 비어 있는 구간으로 열을 나눠 **열마다 위→아래**로 읽음 (끄면 두 열의 같은 높이 글자가 한 줄로 섞임. 합성 2단 이미지에서 읽는 순서 일치율 45% → 99.6%) |
| 공백 정리 | 연속 공백을 하나로 (끄면 벌어진 칸이 공백 3칸으로 남음) |
| 영문 단어 속 0/1 보정 | 소문자 단어 안에서 `t00`→`too`, `w0rld`→`world`, `hel1o`→`hello`. `H2O`, `mp3`, `ver10`, `2026-11-05`처럼 숫자가 섞인 정상 값은 건드리지 않음 |
| 어두운 배경 자동 반전 | 이미지 중앙값 밝기가 낮으면(다크 모드 등) 반전해서 읽음 |
| OCR 언어 / 배율 / 선명화 | 언어는 설치된 OCR 언어가 자동으로 나열됩니다(이 PC는 한국어뿐이며 영어 글자도 함께 읽음). 다른 언어는 Windows 설정 > 시간 및 언어 > 언어에서 해당 언어(OCR 포함)를 설치하세요. 배율 기본 3.0 |
| OCR 직후 자동 복사 | 읽자마자 클립보드에 넣음 (기본 켜짐) |

**출력**: `텍스트 복사`, `텍스트 파일(.txt)로 저장`(BOM·CRLF라서 메모장/엑셀에서 한글이 안 깨짐), `이미지에서 영역만 다시 읽기…`(이미지에서 원하는 부분만 드래그해 그 부분만 읽음), 이미지 복사·PNG 저장.

정확도(합성 한글 문단 이미지, 맑은 고딕): 13·15·18px에서 글자 일치율 96~98.6%, 배율 3.0이 가장 안정적입니다. 글자가 작거나 흐리면 배율을 올리세요. 한국어 OCR은 영문 `o`/`l`을 숫자로, 한글 일부(`처리`→`저리`)를 틀리게 읽는 일이 있으니 중요한 글은 원본과 대조하세요.

### 단축URL 캡처 (운영 > Data&Url캡쳐)
(이전 이름: VDI 테이블 캡처) 단축 URL 관리 화면처럼 한 레코드가 여러 줄로 줄바꿈되는 표에서 원본URL↔단축URL을 뽑습니다.
VDI/원격 화면처럼 UI 요소에 접근할 수 없는 표를 **화면 픽셀만으로** 읽어 엑셀로 옮깁니다.

1. **영역 지정 + 자동 스크롤 캡처**를 누르고 표 **본문**을 드래그합니다. 이후 앱이 맨 위로 이동 → 캡처 → 스크롤을 반복하다가 끝에서 멈춥니다. (캡처 중 마우스를 움직이지 마세요. `ESC` = 중단)
2. 프레임 사이 이동량을 이미지 비교로 찾아 겹치는 부분을 제거하고 한 장으로 이어붙입니다. 고정 헤더·테두리·상태바처럼 스크롤되지 않는 위/아래 영역은 자동으로 제외합니다.
3. 이어붙인 이미지를 로컬 OCR로 읽어 행/열 표로 만들고, 탭 구분 텍스트로 보여줍니다. (직접 수정 가능)
4. 출력
   - **표 데이터 복사** → 엑셀에서 `Ctrl+V` (셀로 분리되어 붙음)
   - **이미지 복사** → 엑셀에서 `Ctrl+V` (그림으로 붙음)
   - **엑셀로 저장** (`표` 시트 + 선택 시 `캡처` 시트에 이미지) / **PNG 저장**

- **영역 지정 캡처 (스크롤 없음)**: 스크롤 없이 지정한 영역을 한 장만 캡처합니다. 이후 OCR/표/복사는 동일합니다.
- **이미지에서 텍스트 선택…**: 캡처 이미지를 원본 크기로 열고, 드래그한 부분만 OCR해서 텍스트로 클립보드에 복사합니다. URL·숫자·문구 하나만 필요할 때 사용하세요. (`줄바꿈 이어붙이기`를 켜면 여러 줄 URL이 한 줄로 합쳐집니다)
- **원본 URL의 `utm_*` 키가 깨졌을 때**(`utmcampalgn`, `utm_campalgn`, `utm=Nkakao`, `utm=20261109`, `utm_source=Nkaka01`): 키를 정확히 일치해야만 인식해서 그 뒤 값 보정이 통째로 건너뛰어졌습니다. 이제 `utm…` 로 시작하는 키는 철자가 깨져도(유사도) 알아보고, `utm` 만 남은 키는 **값으로 추정**합니다(`Nkakao1`→source, `Nkakao`→medium, `recruit`→campaign, 숫자 8자리→term). 그 다음 값 보정(`Nkaka01`→`Nkakao1`)이 정상 적용됩니다.
- **ID에 OCR 잡글자(`『`, `@` 등)가 섞였을 때**(예: `ryOI『TcpYW` → `접속 확인 접속 불가`): `『` 같은 비영숫자가 들어 있으면 서버 요청 자체를 만들 수 없는데(한글 등은 요청줄 인코딩 오류), 이를 서버 문제인 `접속 불가`로 오판해 탐색을 접었습니다. 이제 ① 잡글자가 든 ID는 `접속 불가`가 아니라 **없는 ID**로 취급하고, ② 잡글자 자리를 **알 수 없는 글자**로 보고 그 자리에 글자 모양이 허용하는 후보(알 수 없으면 영숫자 전체)를 넣어, ③ `0/O/o`, `I/l/1`, `Q/O` 같은 혼동 후보와 **함께 조합**(최대 3곳, 알 수 없는 자리를 먼저)해서 서버에 존재하는 ID를 찾습니다. 메모에는 `잡글자 N곳(위치)`가 남습니다.
- **여러 배율로 읽은 결과의 자리별 투표**: 모양이 모순이거나 잡글자가 있는 ID는 그 줄만 잘라 7가지 배율/선명화로 다시 읽고, 읽을 때마다 다른 자리가 틀리는 점을 이용해 **자리별로 투표**한 후보(읽은 그대로 + 자리별 조합)를 먼저 시도합니다.
- **글자 모양 정렬이 한 칸씩 밀리는 문제**(메모에 `글자 모양 불일치 2곳(1,4번째)`처럼 엉뚱한 자리가 지목되고 `접속 확인 불일치`로 남음): OCR 단어 박스가 마지막 글자 앞에서 끝나면 넓은 마지막 글자가 박스 밖으로 밀려, 글리프와 글자가 한 칸씩 어긋났습니다. 이제 정렬 후보를 둘(박스 안 글리프 / 박스 밖까지 포함한 오른쪽 끝 글리프) 만들어 **모양이 더 잘 맞는 쪽**을 고릅니다. (박스를 5·8·11px 줄여도 정상 정렬)
- **`단축 URL 못 찾음`**: OCR이 그 줄의 단축 URL을 놓치거나 `/s/`의 슬래시를 `!`·`|`·`l`·`I`·`1`로 읽어 인식하지 못한 행은, **그 줄 오른쪽 영역만 잘라 다시 OCR**해서 만회합니다. (호스트가 `short.example`과 비슷할 때만 변형 슬래시를 허용해 오탐을 막습니다)
- **원본 URL의 `utm=20261109of`**: 키가 `utm`만 남고 값 뒤에 잡음이 붙어도, 값의 대부분이 숫자이고 6자리 이상이면 `utm_term`으로 추정합니다.
- **접속 확인이 `불일치`로 끝난 단축 URL**(예: `글자 모양 불일치(정렬 실패)` 메모가 붙은 행)을 되찾는 방법:
  - 글자 모양이 OCR 글자와 **모순인 자리**(예: 키 작은 글자 자리에 대문자)는 포기 신호가 아니라 "여기가 틀렸다"는 단서입니다. 그 자리만 모양에 맞는 글자들(폭이 비슷한 글자 먼저)로 바꿔 서버에 대입합니다.
  - `5/S`, `8/B`, `2/Z`, `6/G/b`, `u/v`, `c/e`, `a/o`, `n/h` 같은 **같은 모양 계열**도 후보로 시도합니다(자리별 글자 모양이 허용하는 글자만).
  - 끝 글자 누락과 오인식 한 곳이 **겹친 경우**도 찾습니다. 후보는 가능성 높은 순서(원문 그대로 → 폭이 비슷한 글자 → 한 글자 바꾼 변형)로 시도합니다.
  - 한 번의 복사에서 복구용 추가 요청은 **총 2500회**까지만 보냅니다(복구 불가능한 ID가 많아도 끝없이 늘지 않음). OCR이 읽은 ID 그대로 확인하는 첫 요청은 총량과 무관하게 항상 보냅니다.
- **접속 확인 속도**: 요청 한 번은 약 28ms로 빠른데, 예전에는 후보마다 50ms를 쉬고 하나씩 직렬로 보내서 복구 대상이 몇 건만 있어도 몇 분씩 걸렸습니다. 이제 후보를 **16개씩 묶어 8개 동시 요청**으로 보내고(연결 재사용, 불필요한 대기 제거), 묶음 안에서는 후보 순서대로 판정해서 앞쪽(가능성 높은) 후보가 먼저 이깁니다. 복구 불가 6건이 섞인 25건(요청 2525회)이 약 10초에 끝납니다(예전 방식이면 약 200초).
  - **진행 표시**: 상태줄에 `단축 URL 접속 확인 3/25 · 요청 142회 · ESC = 중단`. **ESC를 한 번 톡 누르면** 이후 탐색을 중단합니다(이미 확인된 결과는 유지).
  - **시간 제한**: ID 하나당 25초, 전체 150초. 제한이나 총량 때문에 접은 ID는 확인필요 열에 `복구 탐색 중단(시간 제한 / 요청 총량 소진 / 사용자 중단)`이 남습니다.
  - OCR이 읽은 ID 자체를 확인하는 첫 요청은 시간 제한과 무관하게 항상 보냅니다.
- **숫자 0 / 대문자 O / 소문자 o 구분** (OCR이 가장 헷갈리는 글자):
  - 모양 규칙(`idfix.py`): `o`는 키가 작고, `0`은 키가 크고 폭이 좁고, `O`는 키가 크고 폭이 넓다. 폭 비율 기준(0.7)은 화면 글꼴(Arial 계열)에 맞춘 값이라 다른 글꼴/크기에서는 틀릴 수 있다.
  - **접속 확인 2단계**: 모양 규칙이 틀려도 되찾도록, 1단계(OCR 결과 + `I/l` 변형)로 안 맞으면 `0/O/o`, `I/l/1` 위치 1~3곳을 같은 계열의 다른 글자로 바꿔 서버에 존재하는 ID를 찾는다 (바꾼 글자가 적은 후보부터, 최대 300회; 3곳이 틀려도 보통 30회 안팎).
  - 접속 확인이 꺼져 있거나 확정하지 못하면 확인필요 열에 `0/O/o N번째 오인식 가능`으로 위치를 알린다.
  - 원본 URL의 숫자 값(`rec_idx`, `utm_term`)은 숫자 자리의 `O`/`I`/`l`/`S` 등을 지우지 않고 `0`/`1`/`5`로 되돌린다 (이전에는 지워서 자리수가 줄었다).
  - 단축 URL 인식이 `/s/`의 슬래시를 `!`/`|`로 읽은 줄(`short.example!s/…`)과 ID가 잘린 줄도 단축 URL 줄로 알아본다 (이전에는 원본 URL 시작으로 오인해 추출 전체가 틀어졌다).
- **단축 URL ID의 끝(또는 중간) 글자가 빠졌을 때**(예: `rOAZcgELG`, `r6KN5yClk` — 10자여야 하는데 9자): ID 길이가 모자라면 세 단계로 복구합니다.
  1. **그 줄만 잘라 다시 OCR**합니다(배율 4.0/3.0/5.0/2.0/6.0, 선명화 on/off). 넓은 표 전체를 한 번에 읽을 때 놓친 글자가 좁게 잘라 읽으면 읽히는 일이 흔합니다.
  2. 그래도 10자가 안 되면 화면의 **글리프(글자 덩어리) 개수와 모양**(키 큰 글자/작은 글자/내려쓰기/점/가는 막대)으로 빠진 위치와 글자 종류를 좁힙니다. 같은 모양이 연속되면 위치가 여럿일 수 있습니다.
  3. **접속 확인**(기본 켜짐)으로 후보를 끼워 넣어 서버에 **존재하는 ID**를 찾아 확정합니다(오른쪽 끝 위치부터, `I/l` 변형 포함, 최대 400회).
  접속 확인이 꺼져 있거나 복구에 실패하면 빠진 자리를 `?`로 표시하고(`rOAZcgELG?`) 확인필요 열에 `끝 글자 누락`을 적습니다. 틀린 9자 URL이 조용히 정상처럼 나가지 않습니다.
- **단축 URL만 선택/캡처한 경우도 정규화·접속 확인이 됩니다.** (이전에는 원본 URL이 있어야만 레코드로 인식해서, 단축 URL 열만 고르면 깨진 OCR 원문이 그대로 복사됐습니다: `http:〃Short.example/s/…`)
  - 접두어가 `http:〃Short.example`, `ttp//`, `fittp://`, `sa ram.in` 처럼 깨져도 단축 URL로 알아보고 `http://short.example/s/ID`로 정리합니다. (`복사하기` 버튼 글자도 제거)
  - 원본 URL이 없으면 화면과 대조할 수 없으므로, 접속 확인은 **존재하는 ID인지**로 합니다. 서버가 실제 공고 URL로 연결하면 유효, 일반 페이지(`/zf_user/`)로 보내면 없는 ID입니다. 그래서 `I`/`l` 후보 중 존재하는 쪽이 정답으로 확정됩니다.
  - 텍스트 선택 창에서 드래그해도 같은 처리를 하고, 상태줄에 `단축 URL N개 · 접속 확인 N/N`이 표시됩니다. (단축URL 캡처의 표 데이터 텍스트도 접두어는 정리됩니다. `I`/`l` 확정은 접속 확인이 켜진 **URL 복사**나 텍스트 선택 창에서 합니다)
- **URL 복사 (원본↔단축, 엑셀 열)**: 레코드(행)마다 **원본 URL / 단축 URL / 확인필요** 3열로 복사합니다. 엑셀에서 `Ctrl+V` 하면 열이 나뉘어 붙습니다.
  - 열 경계에 의존하지 않고 레코드 영역 안에서 URL을 직접 조립합니다(순번이 URL에 섞이던 문제 해결).
  - 원본 URL 보정(`urlfix.py`): 공백 제거, `wwvv`/`wvm`→`www`, `zf-user`→`zf_user`, `view-type`→`view_type`, `Nkaka01`→`Nkakao1`, `rec_idx` 뒤 잡음 제거 등. URL 형식이 바뀌면 `urlfix.py` 위쪽 상수(`HOST`, `KEYS`, `VALUES` …)만 고치세요.
  - 단축 URL ID 보정(`idfix.py`): 글자 **모양(폭·높이)** 으로 `O`/`0`, `1`, `i`, `o`/`p`, 끝 글자 누락을 바로잡습니다.
  - **대문자 `I`와 소문자 `l`은 화면에서 모양이 완전히 같아** 구분할 수 없습니다. 이런 글자가 있는 ID는 `확인필요` 열에 `ID 2번째 글자 확인`처럼 위치를 표시합니다. 해당 ID만 원본과 대조하세요.
  - **I/l 접속 확인 (기본 켜짐)**: 단축 URL ID(와 I/l 후보)를 단축 URL 서버(`short.example`)로 HEAD 요청해, 연결되는 원본 URL의 `rec_idx`가 화면과 같은 후보를 정답으로 확정합니다. **ID만 전송되고 화면 이미지는 나가지 않습니다.** 확인창 없이 바로 진행하며, 서버로 보내고 싶지 않으면 체크를 끄세요(끈 채로 두면 I/l은 '확인필요'로만 표시). `확인필요` 열에 `접속 확인됨/확정됨/불일치`가 기록됩니다. (`shortverify.py`)
  - URL 인식은 **4.0배율 + 선명화**가 가장 정확합니다(기본값). 다른 설정으로 읽은 경우 URL 복사 시 자동으로 한 번 더 읽습니다.
- **텍스트 선택 창에서도 URL 추출·검증**: ① **URL 추출·검증** 버튼은 드래그로 선택한 영역(선택이 없으면 이미지 전체)에서 메인 화면과 같은 방식으로 레코드를 뽑고(접속 확인을 켰다면 검증까지) 결과를 보관합니다. ② **복사 형식**을 고르면 재인식·재접속 없이 바로 클립보드에 다시 복사됩니다.
  - **URL만**: `원본+단축`(2열) / `단축만`(1열) / `원본만`(1열) — 검증 후 엑셀에 바로 붙여넣을 때
  - **전체**: 순번 | 원본URL | 단축URL | 확인필요 (4열)
  - **접속 확인 실패 행 제외**: 접속 확인에서 불일치/접속 불가인 행을 복사에서 뺍니다.
  - 기존 설명: **I/l 접속 확인**(기본 켜짐)으로 서버 접속으로 `I`/`l`을 확정합니다. `선택 해제(전체로)`로 전체 대상으로 되돌립니다. 부분 선택은 원본 URL이 시작되는 왼쪽 끝부터 잡으세요.
- **텍스트 선택 창**: 창이 화면에 꽉 차게 열리고, 드래그 중 가장자리로 가면 자동 스크롤됩니다. **전체 선택 (이미지 전체 OCR)** 버튼으로 전체 텍스트를 한 번에 뽑을 수 있습니다. `줄바꿈 이어붙이기`+`URL 자동 보정`을 켜면 선택한 URL이 공백 없이 보정되어 나옵니다.

옵션과 팁

| 옵션 | 설명 |
|------|------|
| 스크롤 / 휠 칸 수 | 마우스 휠(기본 **2칸**/회) 또는 PageDown 키. 칸 수가 적을수록 프레임 사이 겹침이 커서 이어붙이기가 안정적입니다. 정합에 실패하면 휠 칸 수를 자동으로 절반씩 줄여 재시도합니다. |
| 스크롤 후 대기(ms) | 스크롤 후 **최소** 대기 시간(기본 **1000**). 이후 화면이 안정될 때까지(연속 두 장이 거의 같아질 때까지) 자동으로 더 기다립니다. |

**"이어붙이기 정합 실패 (일치율 N%)"가 나올 때**: VDI는 스크롤 직후 화질이 낮거나 애니메이션 중인 프레임이 찍혀 이전 프레임과 어긋날 수 있습니다. 앱이 먼저 ① 화면이 안정될 때까지 더 기다린 뒤 다시 계산하고, ② 비교 기준을 단계적으로 완화(6→12→20)하며, ③ 그래도 안 되면 휠 칸 수를 절반으로 줄여 재시도합니다. 그래도 실패하면 휠 칸 수를 1로, 대기를 1500ms 이상으로 늘리세요. 매 실행의 일치율·재계산 기록은 `scroll_capture.log`에 남습니다.
| 시작 전 맨 위로 / 영역 중앙 클릭 | 표가 중간에 있을 때, 포커스가 안 맞을 때 사용 |
| 열 간격 민감도 | 슬라이더를 놓으면 열을 다시 나눕니다. 작게 = 열을 잘게, 크게 = 합침 |
| OCR 배율 / 선명화 / OCR 다시 | 글자가 작거나 흐리면 배율(3.0~4.0)·선명화로 다시 인식 (재캡처 불필요) |
| 숫자 점→콤마 | OCR이 `908,800`을 `908.800`으로 읽을 때 보정 |
| 여러 줄 셀 합치기 | 셀 안에서 여러 줄로 줄바꿈되는 표(긴 URL 등)를 **한 레코드 = 한 행**으로 합칩니다. 표 왼쪽 가장자리의 줄무늬/구분선 변화로 레코드 경계를 찾으므로 영역을 표 **왼쪽 끝**에 맞추세요. 경계를 못 찾으면 자동으로 줄 단위로 동작합니다. |

- **여러 모니터**: 영역 선택 오버레이가 모든 모니터를 덮으므로 어느 모니터의 화면이든 지정할 수 있습니다. 스크롤은 지정한 영역 중앙에 마우스를 두고 휠을 돌리므로, **그 위치의 창**(레이어 팝업/모달 포함)이 스크롤됩니다.
- 영역에서 **세로 스크롤바는 제외**하는 것이 좋습니다. (이어붙인 이미지에 섞일 수 있음)
- 한글이 작은 글씨(약 12px 이하)이면 OCR이 틀릴 수 있습니다. 표 데이터는 텍스트 상자에서 고쳐 쓰거나, 정확해야 하면 **이미지 복사**를 쓰세요.
- **대소문자가 섞인 랜덤 ID/URL**(예: 단축 URL `rnilpID2Ry`)은 `I`/`l`/`1` 구분이 안 되어 OCR로 확정할 수 없습니다. 이런 값은 이미지 복사로 보관하거나, 원본 화면의 복사 버튼/텍스트 복사를 쓰세요.
- 이 화면의 OCR 결과는 합계 검증이 없습니다. 금액 등 중요한 값은 원본과 대조하세요.

## 검증과 자동 보정

OCR 오인식을 막기 위해 합계 검증식을 사용합니다.

| 화면 | 검증식 |
|------|--------|
| 통합정산내역 | 거래금액 = 지급액 + 수수료 + 부가세 |
| 세금계산서 | 공급가액 + 세액 = 합계 |
| 수수료 정산 | 세금계산서 (공급가액+세액) = 통합정산내역 한 달 (수수료+부가세) |

- 검증이 어긋나면 배율·선명화를 바꿔 OCR을 다시 시도합니다.
- 그래도 어긋나면 한 자리 혼동(5↔6, 3↔8 등) 수정으로 맞는 후보가 **정확히 1개일 때만** 자동 보정하고, 팝업으로 알립니다. 보정 알림이 뜨면 반드시 이니시스 화면과 대조하세요.
- 후보가 없거나 여러 개면 값을 바꾸지 않고 경고만 표시합니다.

## 영림원 붙여넣기 주의

- 클립보드에는 **행번호~활동센터(8열)** 만 복사됩니다. 관계회사·관리항목까지 붙여넣으면 `Invalid column index` 오류가 납니다. 관리항목은 영림원에서 직접 입력/코드도움으로 선택하세요.
- 수수료 정산 탭은 차변/대변의 빈 쪽을 `0`으로 채웁니다 (양식과 동일).
